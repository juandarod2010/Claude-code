# Investigación de bounties remuneradas — 18 sep 2026

Objetivo: primeros $100 mediante trabajo YA existente con recompensa asignada.
Sin clientes, sin llamadas, sin redes sociales.

## 0. Limitaciones de esta investigación (leer primero)

El entorno de esta sesión bloquea el acceso de red a casi todos los dominios.
Verificado directamente: `github.com`, `api.github.com`, `raw.githubusercontent.com`.
**Bloqueado por el proxy**: `algora.io`, `docs.algora.io`, `bountyhub.dev`,
`opire.dev`, `api.opire.dev`, `docs.omi.me`, `dev.to`.

Consecuencia: todo lo referente a **reglas de plataforma** (países, comisiones,
KYC, PayPal, edad, política de IA) procede de resultados de buscador, **no de
las páginas oficiales**. Está marcado como NO VERIFICADO donde corresponde.
Todos los datos de **issues concretas** (repos, etiquetas, fechas, importes,
número de comentarios) sí son verificados contra la API de GitHub.

## 1. Hallazgo principal

El mercado de bounties de GitHub a fecha de hoy está **dominado por ruido**.

Búsqueda real en la API de GitHub, issues abiertas con la etiqueta de Algora
`💎 Bounty` creadas después del 2026-06-01: **total_count = 4**. Las cuatro
pertenecen a repositorios de granja (`SecureBananaLabs/bug-bounty`,
`xevrion-v2/agent-playground`).

Búsqueda equivalente restringida a `org:tscircuit` (históricamente el mayor
emisor de micro-bounties de Algora) creadas después del 2026-07-01:
**total_count = 0**.

Es decir: **no hay flujo reciente de bounties pequeñas financiadas y
verificables** por la vía clásica de Algora. Lo que queda son restos antiguos,
ya recompensados o con 30–160 comentarios de competencia.

### Reglas relevantes (NO VERIFICADAS — fuente: buscador)

- **Algora**: alta con GitHub OAuth; cobro vía Stripe Express, que exige KYC
  (documento de identidad). Comisión declarada 0% para el desarrollador. Pago
  1–3 días laborables tras el merge. Sus términos **prohíben el acceso robótico
  / automatizado** a la plataforma: usar Claude Code para escribir el parche es
  distinto de automatizar reclamaciones, y sólo lo primero es aceptable.
- **BountyHub**: se reclama enviando la URL del PR desde la misma cuenta de
  GitHub que abrió el PR; paga el creador de la bounty tras aprobar. Stripe
  preferente, **PayPal disponible** cuando Stripe no cubre el país.
- **Opire**: API pública sin autenticación; varios devs pueden abrir PR y el
  maintainer elige cuál mergea (no es por orden de llegada). El dev cobra el
  100% del importe; las comisiones las paga quien financia.
- **Omi / BasedHardware**: se piden bounties mencionando a los maintainers; sólo
  ellos aprueban elegibilidad e importe; se cobra escribiendo a
  `team@basedhardware.com`; **método de pago PayPal**.

### Política de IA

No he encontrado ninguna plataforma de las anteriores que prohíba escribir el
código con ayuda de IA. Lo que sí existe (documentado en investigación de 2026
sobre cumplimiento de reglas de IA en open source) es que **proyectos
individuales** sí lo prohíben o exigen declararlo. La regla operativa es: leer
`CONTRIBUTING.md` de CADA repo antes de escribir una línea, y declarar el uso de
IA si el proyecto lo pide.

## 4. El problema de Omi

Omi es la mejor pista y a la vez la que más hay que verificar antes de trabajar:

- Las 83 issues `[Bounty $X]` **no las abren los maintainers**. Verificado en
  [#14463](https://github.com/BasedHardware/omi/issues/14463): autor
  `hridaya423`, colaborador externo. Varias se titulan literalmente
  "[Bounty proposal] ... ($25 proposed)". Son **propuestas**, no bounties
  financiadas.
- La documentación de Omi dice que hay que filtrar por la etiqueta
  **"Paid Bounty"**. Verificado contra GitHub: esa etiqueta tiene
  **0 issues abiertas y 0 issues cerradas**. No hay ni una sola bounty pagada
  registrada con esa etiqueta.
- [#13478](https://github.com/BasedHardware/omi/issues/13478) (11 sep 2026) es
  un tercero pidiendo públicamente prueba de que se ha pagado a algún
  contribuidor. **Una semana después, sin respuesta de ningún maintainer.**

Conclusión: no hay evidencia de que Omi esté pagando. Tampoco evidencia de que
no. Es una pregunta de un email, no de un fin de semana de trabajo.
